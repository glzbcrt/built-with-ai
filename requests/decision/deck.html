01 / Start with Jev

A model for software, not conversation

Jev, by TypeSafe AI

Evaluates text or JSON against questions. Returns typed values and probability distributions rather than prose.

Why “Jev”?

Named after William Stanley Jevons: cheaper, more efficient intelligence could unlock many more uses.

Think: routing, policy checks, prioritization, and focused evaluations inside ordinary software.

Sources: TypeSafe's Jev announcement · Jev introduction

TypeSafe describes Jev as its first public System One model. Jev currently accepts text, including JSON and arrays of text, not images, audio, or video. Jev is not a Microsoft model; do not imply that Microsoft-Decision-1 or OpenAI shares its weights, architecture, or training recipe.

02 / The name

Why “System One”?

System 1: fast judgment

“Does this ticket request a refund?”

A focused determination given the relevant context.

System 2: deliberation

“Investigate why refunds increased and propose a plan.”

A multi-step task requiring investigation and synthesis.

The name borrows Kahneman's fast/slow thinking metaphor. It is not a claim that a model has a human mind.

Source: TypeSafe: System One

This is a workload distinction, not a universal taxonomy of neural architectures. Fast does not mean infallible. A decision model can hand ambiguous cases to a reasoning model or human rather than trying to solve an entire workflow in one judgment.

  • State: the evidence and policy needed for the decision.
  • Question: one bounded judgment with a clear answer space.
  • Application: validates, thresholds, routes, and authorizes.

Sources: Jev introduction · Microsoft-Decision-1 guide

An HTTP response may be serialized as JSON even though the model itself does not generate a free-form JSON string token by token. Separate the API wire format from how the model produces its decisions. A typed answer is not authorization to execute an action.

04 / Question one

Predicate / Noul: “Is this true?”

Express eligibility

“Is this order eligible for express fulfillment based on inventory, destination, and risk?”

A probability, not a verdict

Illustrative answer: 0.93

An estimate that the condition is true; your code chooses what to do with it.

predicate in OpenAI Decisions; noul in Jev and Microsoft-Decision-1.

Specify the condition clearly. Missing evidence is not automatically proof that it is false.

Sources: Noul · OpenAI question types

0.93 is made up for teaching, not captured from a request. The APIs use different response field names; this slide illustrates the semantic value rather than a portable response object. Define how unknown or conflicting evidence should be handled and evaluate that behavior.

Choice categories are not ordered. A forced answer from an incomplete option list can be semantically wrong while remaining perfectly well typed. Consider the top probability, uncertainty, and business cost when deciding whether to route or escalate.

06 / Question three

Score: “How much, on this rubric?”

Define an ordered scale, not a vague “rate this out of ten.”

IndexUrgency levelIllustrative probability
0Low: no time pressure0.05
1Normal: routine shipment0.15
2High: shipping cutoff approaching0.60
3Critical: commitment immediately at risk0.20
Score = Σ index × probability = 1.95
For OpenAI Decisions and Microsoft-Decision-1, a score can fall between levels.

Sources: OpenAI score semantics · Microsoft score semantics. Synthetic values.

The arithmetic is 0 times .05 plus 1 times .15 plus 2 times .60 plus 3 times .20, or 1.95. The scale runs from zero to three, not zero to one hundred. A score is not the probability that a condition is true. Treat it as rubric-based ordering, not an absolute measurement of urgency.

07 / Inside Jev: inference

Parallel decisions, not a paragraph

Generative response

Produce successive text tokens, each conditioned on earlier tokens. Parse the output if your code needs a decision.

Jev's published approach

A decision-focused architecture and parallel sampler produce bounded outputs. Questions evaluate independently against the same state.

Conceptual path: encode context + questions → evaluate allowed outcomes → return typed values and distributions.

The path is a teaching abstraction, not a disclosed layer diagram. Do not assume Jev's implementation applies to other vendors.

Sources: Jev announcement · Parallel question evaluation

The announcement describes a new architecture and parallel sampler but the sources cited here do not provide a full layer-by-layer specification, parameter count, or exact forward-pass count. Avoid inventing an encoder, classification head, or softmax implementation. Questions in one Jev call are independent: one answer is not fed into another. Use a second call when a later question needs an earlier answer. JSON mode in an LLM constrains text output; it does not by itself establish this inference architecture.

08 / Inside Jev: training

Optimize the uncertainty, too

RLHF

Human feedback: optimize responses people prefer.

RLVR

Verifiable rewards: optimize outcomes that can be checked.

RLCD

TypeSafe's reinforcement learning for calibrated decisions: optimize decisions and their probabilities.

If a model assigns 0.8 to many events, calibration asks whether roughly 80% of those events occur.

A population-level property, not a guarantee about one answer. These are training objectives, not a complete or exclusive training recipe.

Source: TypeSafe's AI primer

Attribute RLCD to TypeSafe, not to Microsoft-Decision-1 or OpenAI. The public primer does not disclose a complete reward formula, dataset, or training implementation. Evaluate calibration on representative local data, especially after a domain shift. Constrained outputs prevent arbitrary prose; they do not prevent incorrect classifications.

12 / Compose judgments

One incident. Several atomic questions.

Checkout errors at 38%; connection pool at 99%; a recent deploy; rollback requires approval.

Ask the model

Is production affected?
Is rollback supported by evidence?
Which specialist should diagnose?
How severe is the impact?

Keep in code

Enforce approval rules.
Apply evaluated thresholds.
Escalate uncertain results.
Log the evidence and outcome.

A recent deployment is evidence to investigate, not proof that rollback is the correct action.

Local walkthrough: request 5 in Microsoft-Decision-1 and OpenAI Decisions.

Invite the audience to distinguish evidence, judgment, and permission. A model can recommend inspecting database metrics without having database credentials. Policy constraints such as human approval should remain hard checks, not optional natural-language suggestions.

13 / Put it to work

Typed does not mean true

  • Define: atomic questions, complete options, concrete rubrics.
  • Evaluate: labeled cases, hard negatives, missing evidence, and domain shifts.
  • Measure: decision quality, calibration, latency, and cost.
  • Control: deterministic policy checks, explicit review paths, and audit logs.
Use a decision model for a bounded judgment.
Use a reasoning model or human when the task needs investigation or explanation.

Further reading: System One workflows · Foundry threshold guidance

There is no universally safe probability threshold. Evaluate false positives and false negatives against the real business costs. Do not treat a model's probability as a security boundary or a substitute for authentication, authorization, deterministic validation, or human approval.
