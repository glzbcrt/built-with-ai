How it works

The model processes a prompt token by token, building internal state (the KV cache) for each one. If a new prompt starts with exactly the same tokens as an earlier one, that state can be reused instead of recomputed.

Two consequences you can test: (1) only a shared prefix counts — an identical sentence in the middle of a prompt gets no cache hit if anything before it differs, and (2) caching works in blocks (try the slider): a partial final block is stored, but only an identical prompt can reuse it. At block size 1 it is a pure token-by-token prefix match.

Practical tip: put stable content (system prompt, documents, examples) first and the changing question last.
